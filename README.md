# SnowRunnerTools

## Build, test and publish

Open `SnowRunnerTools.sln` from this directory. Install the .NET SDK selected by
`global.json`; the desktop application and its regression checks require Windows.

```powershell
pwsh ./tools/Build.ps1
pwsh ./tools/Test.ps1
pwsh ./tools/Publish.ps1
```

Builds and generated fixtures go under the ignored `artifacts/` directory. Desktop
publishes go to `artifacts/publish/SnowPakTool.Desktop/`. An existing release folder
can be selected with `pwsh ./tools/Publish.ps1 -OutputPath <folder>`.

The default test command runs the isolated smoke checks listed in
[tests/README.md](tests/README.md). Other maintained regression executables can be
selected explicitly; some require a game workspace or manipulate application
preferences. Historical checks in `tests/Legacy/` are retained separately.

The source repository does not contain game PAKs, extracted workspaces, installed
game files, or generated releases. Existing embedded UI thumbnails and their
attribution notices are application resources.

See [Source layout](docs/SOURCE_LAYOUT.md) for the feature folders and guidance on where to put new code.
SnowRunner Tools is a set of utilities to handle [SnowRunner](https://snowrunner-thegame.com/) data files.

Note that its PAK files are really ZIP files with a particular layout and can be extracted with any common tools like 7-Zip,
but require a bit of special handling to create.

**BE SURE TO MAKE NECESSARY BACKUPS FIRST**

## SnowPakTool
* Compress files into a single PAK file,
* Create _initial.pak\pak.load_list_ (initial assets loading order),
* Create _shared_sound.pak\sound.sound_list_,
* Packing/unpacking _initial.pak\initial.cache_block_ (various game data: UI layout, settings, translations, etc.)

### SnowPakTool Desktop UI


**Start → Save shared preset… / Load shared preset…** shares the complete gameplay setup in a versioned `.snowpreset` file: current truck/engine/winch/frame-addon/XP previews, staged edits, map-truck drafts and applied map edits, upgrade results, ownership, truck groups/tiers, region difficulty/progression, randomizer rules and workspace planning settings. Export renders drafts in an isolated workspace without applying or clearing the sender's edits. Randomization choices are stored as concrete results; loading never rerolls. The file contains Brotli-compressed copy/literal differences against preserved originals, rather than full PAKs or unchanged assets. Machine paths, installed game archives, player saves, window settings and caches are excluded.

Loading checks the complete preserved initial-PAK content fingerprint and the exact original archive hash of every shared map. Use the same app build and game/original files; a matching game version alone does not prove that two modified baselines match. Select the installed map folder in Map trucks if needed. When local previews, pending edits, drafts, applied changes or another staged preset exist, Load shows a resizable, sortable review of the local changes that will be replaced: applied file edits, staged editor values, unsaved previews, map drafts, upgrade plans, an existing staged preset, and changed planning/settings. The table lists targets, before/after local values, and the preset outcome; hover for full values or copy selected rows. Cancel keeps the current setup. Replace with preset stages the preset as a complete replacement; old pending edits are ignored while it is staged. Apply backs up and clears superseded pending stores and local outputs absent from the preset, so they cannot leak into the shared result. Discarding before Apply retains existing saved work. Original-file compatibility checks still apply. Load writes only a persistent staged snapshot, with before/after initial-file values visible on Start; planning settings remain unchanged until **Apply pending changes**. All tabs remain available for read-only browsing while the snapshot is staged: scrolling, selection, sorting, header filters, region filters, logs and tooltips stay usable. Editing controls, setup checkboxes, drag-and-drop, randomization/reset/staging buttons and raw-file editing are disabled until the preset is applied or discarded. **Discard shared preset** removes it without changing outputs. Apply verifies all baselines again, prepares every output, preserves old files/settings under `preset-history`, and rolls back completed replacements on failure. The app refreshes its planning and editor state after Apply. Pack a new initial PAK and install the separate map outputs manually.

The same preset applied to matching originals produces the same initial and map contents. Initial PAK packing uses ordinal cache-entry ordering and fixed ZIP timestamps/attributes, so the same app build also produces byte-identical archives across workspace paths, file modification times and system cultures. For the sender to reproduce the complete exported preview, stage and apply all included previews/drafts, or load that same preset into a clean workspace. Automated checks cover cross-workspace initial/map SHA-256 equality, compact deltas, preview capture, staging/restart reads, baseline conflicts, malformed presets and rollback after a locked-file failure. Start lists/counts and applies only staged changes. Drafts and staged choices survive reloads and restarts, but neither action writes map files. A draft on the same map as an applied staged change is retained and rebased to the updated map offsets/hash, so it can be staged later. Existing plans from versions without a staging flag remain staged for compatibility. Only **Start's unified changes list** writes the staged changes. The map writer updates both scene size boundaries, preserves the PAK entry order and each entry's compression method, and copies unrelated ZIP records unchanged. Original maps and previous edited versions remain backed up under `workspace/region-maps/backups`. **Repair saved maps** rebuilds outputs produced by the older writer using their original archive layout, while retaining the selected trucks. Repair verifies the unchanged scene payload and unrelated archive contents before replacing a workspace output; it never writes installed game files. Reload and review any pending replacements after repairing their source map.

Regions-Trucks uses `workspace/region-maps/backups/<map>/original.pak` (or `original.bin`) as the baseline whenever present. Saved workspace maps override that baseline and pending replacements override the displayed rows. Deleting an updated map therefore restores the backed-up placements on reload or when returning to the tab. Maps without a workspace backup are read from the selected map folder. Workspace backups and updates can also be used without the installed map folder. Truck cells that differ from the preserved original placement are highlighted: yellow for pending replacements and green for applied replacements. Hovering a truck cell shows the original truck tile on the left and current truck tile on the right, with a right-pointing glyph arrow between them and their IDs below, including after repeated replacements and reloads. The preview follows sorted rows and closes when scrolling or leaving the cell; equipment tooltips remain available. Restoring the original model clears the change highlight.

As an example, here's how to increase first and third person FOV slider ranges (they're normally limited to 130 max):

```bat
set client=D:\Games\SnowRunner\en_us\preload\paks\client

7z x -o"initial-pak" "%client%\initial.pak"
snowpaktool cb unpack --allow-mixing "initial-pak\initial.cache_block" "initial-pak"
del "initial-pak\initial.cache_block"
patch -u -i mods\fov_sliders_180.diff "initial-pak\[ps]\ui_settings_controller.sso"
del "%client%\initial.pak"
snowpaktool pak pack --mixed-cache-block "initial-pak" "%client%\initial.pak"
```

**Randomizer > Map upgrades > Apply staged upgrades** applies only the saved upgrade snapshot: pickup replacements in level settings plus their exploration flags. It leaves other staged PAK edits and later unstaged upgrade drafts intact. This writes the workspace overlay; pack a new initial.pak from Start and install it for the game to use the changes. Input archives and installed files remain untouched.

Truck properties: Reset to original values previews a restoration against the values currently in files. Stage changes persists that restoration for Start > Apply pending changes. Reset and Stage explicitly report when the files already contain those values and there is nothing to apply; an empty staged list clears any previous staged truck-property edits.

Editors > Addons shows current (original) values for Price, Unlock rank and Exploration unlock. Revert unstaged edits restores the saved snapshot; Revert staged changes clears it. Blank removes the local attribute and restores inheritance. Apply validates exact source, definition and attribute targets before writing; original files and unrelated properties remain intact. Later upgrade randomization can recalculate exploration flags. Packing and installation remain manual.

Editors > Addons follows Truck properties for Price, Unlock rank and Exploration unlock: editable cells, current (original) formatting, green applied/amber preview highlights, Reset selected to original, Reset to original values across both views and filters, Stage changes, Revert unstaged edits and Revert staged changes. Reset restores all three supported properties, including removing local attributes absent from the original. Truck properties, Addons and Frame addons each have a Show changed only toggle button. It includes preview/staged differences from current files and applied values differing from preserved originals. In Frame addons this includes fuel and tracked price/rank/exploration changes. It combines with header filters and stays enabled across reloads and addon-view switches; turning it off retains other filters. The toggle changes visibility only: Stage and global reset actions still include hidden rows.

Frame addon fuel multiplication skips explicit zero capacities, rounds nonzero results to 5 L, and uses 0-10,000 L bounds. Restoring fuel keeps the exact original integer capacity without rounding it. Truck fuel bounds are unchanged. Truck properties reset also preserves original attribute absence: an introduced UnlockByExploration=false is staged as an attribute removal, so Start no longer retains Not present -> false after reset/apply. XML difference auditing compares parsed properties and ignores whitespace, line-ending and encoding-only differences; real added/removed/changed attributes remain listed.
