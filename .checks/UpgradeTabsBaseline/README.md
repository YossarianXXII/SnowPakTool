# SnowRunnerTools
SnowRunner Tools is a set of utilities to handle [SnowRunner](https://snowrunner-thegame.com/) data files.

Note that its PAK files are really ZIP files with a particular layout and can be extracted with any common tools like 7-Zip,
but require a bit of special handling to create.

**BE SURE TO MAKE NECESSARY BACKUPS FIRST**

## SnowPakTool
* Compress files into a single PAK file,
* Create _initial.pak\pak.load_list_ (initial assets loading order),
* Create _shared_sound.pak\sound.sound_list_,
* Packing/unpacking _initial.pak\initial.cache_block_ (various game data: UI layout, settings, translations, etc.)

### SnowPakTool Desktop UI

**Start → PAK** groups truck XML changes into one brief row per truck and state, using the localized truck name. The summary shows up to three readable field/value changes (for example fuel capacity, price, unlock rank, engine or winch compatibility), followed by a count of further changes. Hover for every original field, before/after value and source path. Pending and applied summaries retain their distinct colors. Rank XP, shared engine/winch definitions, addon files and other general edits remain separate entries. Grouping affects display only; Apply and pending counts still use the full underlying edit list.

**Start → Map files** groups truck/equipment changes (obtainable, mission and manual) across maps into one summary per region and state. Applied and pending rows retain their distinct colors. Summaries show change/map counts without replacement identities; hover to see the contributing map IDs and counts. Map repair and other metadata warnings remain separate rows. **Discard selected pending changes** discards the staged changes represented by that region summary in one atomic update; other regions, applied assignments and unstaged drafts remain intact. Pending badges and Apply still count/use individual changes.

In **Randomizer → Map trucks**, **Reset selected to original** resets every truck matching the selected regions and current column filters, regardless of the highlighted row or scroll position. Rows excluded by filters remain untouched. The existing region-wide and all-truck reset actions remain available. Reset updates the draft; Stage and Start → Apply are still required for map writes.

The comparison/reset baseline is the first preserved input under `region-maps/backups/<map>/original.pak` (or `original.bin`), rather than a verified factory game archive. If the input was modified before its first backup, that modified input is the baseline. Without a backup, the loaded source is treated as the baseline; a placement that cannot be matched to an existing backup can fall back to its current model for display, with original equipment unavailable for reset. Backups are preserved across subsequent replacements, but their presence alone does not prove that they contain vanilla game data.

**Randomizer → Truck randomization → Missions** uses the same editable rule list, compact add/edit/remove glyphs, run button, Stage changes button, default-hidden detailed logs and region completion messages as Obtainable. Its saved **Easy / Moderate / Hard** selector controls vehicle weight only: Easy favors lighter models, Moderate gives equal model weights, and Hard favors heavier models. Vehicle weight is the sum of bare vehicle physics bodies, resolving shared/local body templates and inherited definitions; cargo, frame addons and truck tier/class labels do not determine weight. Equal masses share a weight percentile, with a broad, linear bias capped at 3:1 between the favored and opposite ends of the weight range (previously about 20:1). All weights retain substantial chances in every mode. The pool uses enabled trucks, including unranked models, across all classes. Original mission addon requirements are ignored and replacement default equipment is used.

Mission tires use **region difficulty only**, independently of finalized progression and the weight selector: D favors Highway, C All-terrain, B/A Offroad, and S Mudtires, with a 20% adjacent-category variation draw clamped at the endpoints. Unsupported categories fall back to the nearest supported category; use the smallest supported size and first variant. Regions without a difficulty tier and vehicles with unreadable mass are reported and skipped. Selection prioritizes models unused across all regions, then globally least-used models, with regional variety as a tie-breaker. Existing randomization assignments, pending draft/staged replacements and applied manual edits visible in the catalog all count toward usage; a placement represented in both an assignment and a draft counts once. Reset drafts release their prior model usage. This global count carries between regions and across runs, including later ownership changes. Saved assignments stay fixed across mode/ownership changes, and mission rolls do not consume the obtainable HEAVY_DUTY exception allowance. Existing empty Missions rule lists receive these defaults once; custom notes are preserved and later intentional empty lists stay empty. Former unedited default mission weight/variety notes migrate to the broader weight mix and global variety rules; custom notes are retained. Rule prose remains editable notes; it does not change the algorithm.

Only mission-only map placements in owned regions are processed; obtainable and unverified placements are excluded. Original task IDs and reward/removal scripts remain unchanged. Results and original/current comparisons appear in **Randomizer → Map trucks**, with the existing reset actions. Randomization saves a draft only. **Stage changes** in either pane or Map trucks stages all map drafts; **Start → Apply** writes staged maps with the original archives preserved. Both randomization buttons are disabled during a run or staging operation. Mission logs hide replacement identities; optional detail entries reveal tire fallbacks in their original order.

Truck randomization controls sit directly below the actual rule text, with scrolling when longer rule lists need it. Logs, details and rule text use the configurable very light gray (RGB 248/248/248) **Text areas** background. In **Editors -> Winches**, Truck winch compatibility uses the existing whole-tab search, header filters for truck/class, and Compatible / Not compatible filters for each winch class. The header filters leave compatibility edits intact. Shared table headers reserve space only for icons that are present, with compact arrow/funnel spacing and unpadded text.

Sortable/filterable tables share the same header controls across Owned content, Engine compatibility, Truck properties, Map trucks, Cargo and its details, replacement candidates/comparisons, Start change lists, rank XP values, and file-conflict review. Click a heading to cycle ascending -> descending -> off; off restores the original/model order while retaining column filters. Funnels open checkbox filters, filled blue when active; right-click headers for explicit sort/filter/reset commands. Filters combine across columns, support numeric and blank values, and remain applied when the table refreshes. Class/DLC/tire/availability dropdown filters now live in their respective headers. Map availability keeps unverified placements visible and editable. Region tiles, column visibility and comparison-mode controls retain their separate purposes; the XP region list continues to follow Region progression. Sorting/filtering affect the display, so rank values retain their rank identities, row actions retain their record identities, and hidden records remain part of staging/Apply as before.

On **Planning -> Owned content**, the left side stacks **Region DLCs**, **Truck DLCs**, and **Other DLCs** vertically, beside the Truck list. Each DLC pane has an independent borderless chevron: down to collapse, right to expand. Collapsing hides that table and its Select all control while keeping the title and chevron visible; remaining expanded panes share the space. All three can be collapsed and reopened. The glyphs support keyboard activation and identify their action in tooltips and accessibility labels. Ownership selections remain intact. The Truck list filters live in the column headers: click a heading to cycle ascending, descending, then off. Off restores the original base-game/release order and removes the arrow; active filters stay in effect. The active sort arrow appears at the right of the heading. Click the adjacent funnel to open checked filter choices for that column. Filled blue funnels indicate active filters; hover for selected counts. Multiple column filters combine, and sorting keeps the filters. Right-click a header for sort, filter and clear-filter commands. Filter choices affect the displayed rows only.

Navigation uses four main tabs and at most one sub-tab row: **Start** (workspace, pending changes, Apply and packing); **Planning** (Owned content, Truck tiers, Region difficulty, Truck groups); **Randomizer** (Region progression, Truck randomization, Map trucks); and **Editors** (Truck properties first, Engines, Winches, Addons, Experience / Ranks, Cargo). Each group remembers its selected sub-tab while the app is open. Both rows strongly mark the active tab with a solid system highlight, bold contrasting text, and an underline; native keyboard navigation remains available. Start shows the pending-change count when refreshed or navigating between pages. A Settings gear at the top right opens the color settings in a separate window, with no additional tab row. Settings supports the same double-Shift search. Map truck results remain in their own Map trucks sub-tab; randomization logs do not reveal replacement choices.

The **Randomizer** main tab contains **Region progression** first, followed by **Truck randomization** and **Map trucks**. **Region progression** offers Easy, Normal, and Hard radio buttons and a Randomize button that automatically saves the suggested play order. It always starts in the easiest populated difficulty tier (D is easiest, S hardest), then uses a rising difficulty target with weighted variation; Hard favors tougher regions earlier. Unsorted regions go last when generating. The wrapping region tiles use the same soft background tints as the Region Difficulty tier panes (neutral gray for Unsorted) with contrasting text, and show larger, heavier circular position numbers in badges matching the header height, and read left to right then continue on the next row. They use the same drag preview and insertion marker as the tier lists; manual reordering saves automatically and renumbers the badges. Previous randomization restores one prior order kept in memory for this session. Finalize saves and locks the current order, disabling Randomize, Previous, difficulty controls, and tile moves; it becomes Unlock to allow changes again. The finalized state survives restarts. New regions append to the saved order without moving existing placements; tier and difficulty changes do not reroll the order. This uses all regions listed by the current workspace and does not modify game data. **Truck randomization** displays side-by-side Obtainable and Missions rule panes. The Obtainable pane starts with the six randomization rules (ownership, class, variety, progression, tires, and required addons); Missions starts with the five mission randomization rules. Each pane has a compact + glyph to add a rule; every rule has pencil and trash glyphs to edit and remove it. Tooltips identify each action. Edits save automatically between sessions; empty lists stay empty. The Obtainable pane can randomize owned obtainable placements after Region progression is finalized. It uses ranked owned trucks from the same app class, a progression-weighted truck tier draw, a repetition penalty, difficulty-weighted tire categories, and the smallest supported tire size/first variant. Regional variety counts saved assignments, pending edits, and new selections together. HEAVY_DUTY selections favor trucks within one target tier, widening by one tier when that offers less-used compatible models, then choose among the least-used regional models before applying progression weights. This prevents a lone low-tier candidate from being selected repeatedly while suitable alternatives exist. Other classes receive an additional strong regional repeat penalty. Necessary reuse and tier-band widening are explained in detailed logs. If the compatible nearby pool has fewer than three trucks or all its trucks have been used, there is an 18% chance of a similarly ranked OFFROAD substitute, capped at one per five saved HEAVY_DUTY assignments (the first opportunity is assignment five). The exception is one-way, still requires ownership and addon/tire compatibility, and is reported only in detailed logs. The cap includes persisted assignments across runs and ownership changes; existing assignments stay fixed. Required listed addons are preserved through compatible equivalents (including sideboard capacity); incompatible trucks are rejected and another candidate is tried. Unranked regions/trucks, unverified placements, missions, and unavailable configurations are not guessed. Saved assignments remain fixed across restarts and ownership changes. This pane shows region completion/error messages without revealing choices. Show detailed logs is off by default; enabling it reveals recorded placement messages in their original order, including tire-category variation, compatibility fallbacks, and rejected candidates, without naming replacement trucks. Actual trucks and equipment are shown in Randomizer → Map trucks. That tab has Reset truck to original, Reset selected regions to original, and Reset all to original buttons. Reset all covers every loaded placement across all regions regardless of selection or table filters. Reset clears assignments and previews restoration of the original model and exact map equipment. You can rerandomize a reset preview immediately, without applying the restoration first. Start → Apply map changes performs all map writes, carrying the chosen tires/addons through preview and Apply. Start also hides randomized replacement details so applying does not spoil the result. Old manual pending-change arrays are read and upgraded atomically when saved. Mission randomization is available in the matching Missions pane. Editable rule text remains descriptive notes; editing prose does not change the implemented constraints.

A simple Windows Forms frontend is in `src/SnowPakTool.Desktop`. Its first tab handles PAK unpacking, workspace merging, and repacking. The **Experience / Ranks** tab displays and edits the `rankExp` progression values in `[ps]/rank_settings.sso`, shows the 17-season maximum of 1,163,997 XP, provides a collapsible region XP checklist with a selected subtotal, and totals the current rank progression values needed to reach level 30. The region checklist and graphs follow the saved Region progression order, refreshed whenever the editor is opened; regions absent from that order append in the usual release order. Local sorting/dragging and the old separately saved XP region order no longer override it. Included-region selections, curve controls and staged rank XP are preserved. The updated XP progression uses an exponential curve, with a steepness slider beside the curve preview and an XP reduction slider below it; the reduction amount appears beneath that slider. Opening the tab, restoring control settings, or adjusting the preview does not stage any file changes. Save rank XP saves an explicit snapshot in per-workspace app preferences. Start → Apply pending PAK edits writes only that snapshot to the workspace, preserving the original; later preview edits are excluded until saved again. Staged XP survives restarts and is listed on Start even before the rank tab is opened. Apply staged rank XP before packing.

All desktop tabs share one double-Shift text search with a three-character minimum. It searches the current tab and selected sub-tab, highlighting labels, values, table text and detail data without filtering rows. Enter focuses the first match; Esc, clicking elsewhere, or switching tabs/windows closes search.

**Editors → Truck properties** lists truck names, classes, assigned tiers, fuel capacity, unlock rank, price, store countries, differential lock and verified obtainable regions/maps. Region information reuses Regions-Trucks, including randomized replacements and pending map changes; unavailable map data and unverified placements are not guessed. Click column headers to sort, or **Order by tier** for SS through FX followed by Unsorted. Hover a truck name to show its usual tile. Tier cells use exactly the soft tier-pane background tints. A five-character horizontal line replaces the missing verified-placement message; the explanation remains in its tooltip. Edit numeric cells individually; changed fuel values also round to the nearest 5 litres. The compact fuel multiplier slider selects 0.5× through 3× in 0.5 steps; **Multiply all fuel** multiplies the currently displayed, explicitly defined fuel capacities, rounds to the nearest 5 litres (ties upward, minimum 5 L), and bounds the results to the allowed range. Moving the slider alone does not change values, and repeated button clicks multiply again. Changed numeric cells show the preserved original in parentheses, e.g. **160 (80)**, with amber preview/staged and green applied highlights; editing and sorting use the numeric value. The **Columns** checkbox dropdown controls visible columns; Differential Lock is hidden and unchecked by default. Blank/inherited values stay unchanged. **Save preset / Load preset** exports/imports a versioned JSON snapshot; loading only previews matching workspace values. **Stage changes** persists an explicit snapshot across restarts and lists it on Start even before opening this tab. **Revert unstaged edits** restores that snapshot, **Revert staged changes** clears it, and **Reset to original values** previews the preserved baseline. Only Start → Apply pending PAK edits writes the updated workspace files, preserving unrelated XML and the original files; later unstaged edits are excluded. Reload properties discards unstaged edits. Staged values changed externally are rejected during Apply and can be reloaded and restaged.

**Generate unlock ranks** in Truck properties previews a new unlock-rank plan from the saved truck tier list (FX/D early through S/SS late). Separate Easy / Normal / Hard radio buttons save per workspace and target soft caps of about ranks 15 / 20 / 25. All modes use wider independent per-truck variation: Easy is broadest and early-biased, Normal has a medium spread, and Hard unlocks later with a narrower but still substantial spread. Original game class is used for starter coverage only; other ranks depend on tier and independent random draws. There is no class balancing, rank-spacing enforcement or gap filling, so multiple trucks may share a rank and empty ranks can still occur. Soft caps are not limits: individual trucks can unlock above them, up to rank 30. Unranked trucks retain their current preview ranks unless needed as a starter. Starter coverage uses only the first region in the saved Region progression order and its existing store country. It sets one owned, directly purchasable Scout and Offroad starter to rank 1, and one Highway, Heavy Duty and Heavy starter to a randomly selected rank from 1-3; app-only Logging/Farming Tractor classes are ignored. The lowest-rated eligible candidates are preferred, with price breaking ties. Discovery/task-locked trucks and unowned DLC cannot satisfy starter coverage. Country availability remains read-only. If no eligible truck of a game class is sold in that first store country, the generator reports that class gap and proceeds with the achievable rank changes. Missing first-region/store definitions explicitly skip starter coverage. Other countries receive no starter guarantees. It does not add country assignments or remove task locks. Each generation asks whether to update UnlockByExploration, with Yes strongly recommended and selected by default; No changes ranks only and Cancel changes nothing. Yes sets true for trucks in current obtainable map placements (including randomized/pending replacements and task rewards), and false for other trucks; mission-only vehicles do not count. The table shows true/false with original values and change highlights. Starter eligibility uses these resulting flags, so a discovery-locked truck cannot satisfy immediate buyability. With no maps loaded, map-read warnings or unverified placements, uncertain flags are preserved and explained in the log; confirmed obtainable trucks can still be set true after partial reads. The report lists changed, unchanged and skipped exploration flags. Generate again after changing map-truck assignments, then stage both truck properties and map changes before applying. Staging, Apply, presets, revert and reset handle numeric values and exploration flags; legacy version-2 Country payloads are ignored so older pending files/presets cannot apply unintended country edits. Numeric-only pending arrays and version-1 presets remain readable. Selecting difficulty and generating do not edit game files or stage the preview. Generation opens a resizable, copyable report, which can be hidden with Show unlock log. It records the seed, difficulty, first region/store country, coverage warnings and changed/unchanged/skipped totals. Each truck lists its before/after preview rank, file and original ranks, and the reason for its result, including equal random draws, missing tiers/ranks and exclusions from starter coverage. UnlockByExploration=true keeps a truck store-locked until discovered on a map; rank changes do not clear that separate requirement.

The **Planning** tab contains **Truck tiers** and **Region difficulty**, alongside ownership and truck groups. **Region difficulty** ranks all regions found in the workspace in fixed S, A, B, C, and D tiers, from hardest to easiest: S red, A orange, B yellow, C green, and D blue. The same colors appear on Region progression tiles; truck tier colors are independent. It shares truck tier-list drag-and-drop, reordering, directional scrolling, palette colors, and search, with offline region thumbnails and season labels. Region rankings save automatically in their own file, independently of truck rankings.

ANK MK38 Civilian (`ank_mk38_ht`) is included in the base truck catalog even though its XML is stored under `_dlc/dlc_6` without a truck entitlement entry. It appears in Planning → Truck tiers → Unsorted until ranked, and shares that assignment with Truck properties. Its tier is independent of the regular ANK MK38.

Tire randomization always uses **Hard** calculations; there is no tire-difficulty selector, and legacy saved choices are ignored. Every new placement rolls independently. The first region in the finalized order requests 99% Highway and 1% All-terrain, even if it is ranked S or is the only region. Later tire weights blend progression position (80%) with region difficulty (up to 20%, introduced gradually), interpolating from Highway toward better categories while keeping weaker tires in the mix. In the final S-tier region, Highway / All-terrain / Offroad / Mudtires odds are 10/25/35/30%. Truck compatibility can change the actual category to the nearest supported one; the smallest supported size and first variant are still used. Detailed logs show position, region tier, Hard tire calculations, requested odds and fallbacks without naming replacement trucks. Existing saved/pending assignments stay fixed; use Map trucks reset before rerandomizing them. Default tire-rule notes are updated when loaded; custom notes and empty lists are preserved.

Run it from the repository root with:

```powershell
dotnet run --project .\src\SnowPakTool.Desktop\SnowPakTool.Desktop.csproj
```

The UI uses the original SnowPakTool cache-block and PAK writer classes and writes to a new output file without replacing the input archive.

Manual replacements, randomization and resets first create persistent **Draft** map changes. **Stage changes** appears in both Randomizer → Truck randomization and Randomizer → Map trucks; either button stages the same complete current draft across regions, including hidden rows. The table distinguishes **Draft**, **Staged**, and **In files**. Editing a staged placement returns that placement to Draft; other staged placements stay staged. Start lists/counts and applies only staged changes. Drafts and staged choices survive reloads and restarts, but neither action writes map files. A draft on the same map as an applied staged change is retained and rebased to the updated map offsets/hash, so it can be staged later. Existing plans from versions without a staging flag remain staged for compatibility. Only **Start → Map files** writes the staged changes. The map writer updates both scene size boundaries, preserves the PAK entry order and each entry's compression method, and copies unrelated ZIP records unchanged. Original maps and previous edited versions remain backed up under `workspace/region-maps/backups`. **Repair saved maps** rebuilds outputs produced by the older writer using their original archive layout, while retaining the selected trucks. Repair verifies the unchanged scene payload and unrelated archive contents before replacing a workspace output; it never writes installed game files. Reload and review any pending replacements after repairing their source map.

Regions-Trucks uses `workspace/region-maps/backups/<map>/original.pak` (or `original.bin`) as the baseline whenever present. Saved workspace maps override that baseline and pending replacements override the displayed rows. Deleting an updated map therefore restores the backed-up placements on reload or when returning to the tab. Maps without a workspace backup are read from the selected map folder. Workspace backups and updates can also be used without the installed map folder. Truck cells that differ from the preserved original placement are highlighted: yellow for pending replacements and green for applied replacements. Hovering a truck cell shows the original truck tile on the left and current truck tile on the right, with a right-pointing glyph arrow between them and their IDs below, including after repeated replacements and reloads. The preview follows sorted rows and closes when scrolling or leaving the cell; equipment tooltips remain available. Restoring the original model clears the change highlight.

As an example, here's how to increase first and third person FOV slider ranges (they're normally limited to 130 max):

```bat
set client=D:\Games\SnowRunner\en_us\preload\paks\client

7z x -o"initial-pak" "%client%\initial.pak"
snowpaktool cb unpack --allow-mixing "initial-pak\initial.cache_block" "initial-pak"
del "initial-pak\initial.cache_block"
patch -u -i mods\fov_sliders_180.diff "initial-pak\[ps]\ui_settings_controller.sso"
del "%client%\initial.pak"
snowpaktool pak pack --mixed-cache-block "initial-pak" "%client%\initial.pak"
```

## SnowTruckConfig
* Add top-center crane sockets to lift vehicles more easily
* Change customization cameras FOV
* Rename game objects to include detailed info in their names

This example adds a new crane socket to Hummer H2:

```bat
set client=D:\Games\SnowRunner\en_us\preload\paks\client

7z x -o"initial-pak" "%client%\initial.pak"
snowpaktool cb unpack --allow-mixing "initial-pak\initial.cache_block" "initial-pak"
del "initial-pak\initial.cache_block"
snowtruckconfig truck CraneSocket add top-central "initial-pak\[media]\classes\trucks\hummer_h2.xml"
del "%client%\initial.pak"
snowpaktool pak pack --mixed-cache-block "initial-pak" "%client%\initial.pak"
```
